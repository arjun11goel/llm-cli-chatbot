# PromptForge Week 1: LLM CLI Chatbot

A beginner-friendly command-line chatbot built with Python and the Groq API for the PromptForge GenAI & LLM virtual internship at CodGen. The project introduces LLM API calls, role-based conversation history, system prompts, temperature settings, error handling, and JSON conversation exports.

## Features

- **Groq API integration:** `test_groq.py` sends `Hello` to the configured model and displays its response.
- **Conversation memory:** Sends the current conversation history with each request, using `system`, `user`, and `assistant` roles.
- **Three personas:** Patient Coding Tutor, Concise Study Assistant, and Creative Storyteller.
- **Adjustable temperature:** Supports changing temperature between `0.0` and `2.0` during a session.
- **CLI controls:** Help, persona selection, temperature settings, conversation reset, and exit.
- **Error handling:** Handles empty input, missing API configuration, and common API or connection errors.
- **JSON session export:** Saves non-empty chat sessions to timestamped JSON files.
- **Colored terminal output:** Uses Colorama to distinguish chatbot output.
- **Environment-based configuration:** Reads the API key and model name from `.env` rather than hardcoding credentials.

## Requirements and Dependencies

- Python 3.10 or newer
- A Groq API key and internet connection
- `groq` — communicates with the Groq chat completions API
- `python-dotenv` — loads settings from `.env`
- `colorama` — adds colored terminal output

The project uses the Groq Python SDK directly to make the API call and message structure easy to follow.

## Configuration

The local `.env` file contains the API key and model configuration. Its format is:

```dotenv
GROQ_API_KEY=your_groq_api_key
GROQ_MODEL=openai/gpt-oss-20b
```

`GROQ_MODEL` can be set to another model available to the account. The `.env` file is excluded by `.gitignore`; the committed `.env.example` is a template and should not contain a real key.

## Running the Project

From the project directory, activate the Python virtual environment and install the packages listed in `requirements.txt`. On Windows PowerShell, the typical commands are:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

After configuring `.env`, the API test and chatbot can be run with:

```powershell
python test_groq.py
python chatbot.py
```

The first script checks the connection by sending `Hello`. The second starts the interactive CLI chatbot. The initial persona is **Patient Coding Tutor**, and the default temperature is `0.2`.

## Chatbot Commands

| Command | Description |
|---|---|
| `/help` | Displays the available commands |
| `/persona` | Selects one of the three personas |
| `/temperature` | Changes the temperature from `0.0` to `2.0` |
| `/clear` | Clears earlier turns while keeping the current persona |
| `quit`, `exit`, or `0` | Ends the session and saves a non-empty conversation |

Empty user messages are ignored. The application also attempts to save a non-empty session when the chat is interrupted with `Ctrl+C` or end-of-input.

## Conversation Memory

The chatbot maintains a list of role-based messages and sends that history with each model request:

- **`system`** defines the active persona and behavior.
- **`user`** contains the user's messages.
- **`assistant`** contains responses generated by the model.

This allows follow-up questions to use information from earlier in the same session. `/clear` resets the conversation turns while retaining the active system prompt.

## Prompt Engineering and Reflections

The three personas can be compared by asking each the same question and observing differences in tone, length, examples, and structure. The temperature setting can be tested with the same prompt at different values to observe changes in response variation; higher temperature does not guarantee a better or more creative answer.

`reflections.md` records the system-prompt experiment, temperature observations, conversation-memory test, and the main lessons learned during Week 1.

## Session Export

When a non-empty session ends, the chatbot saves a timestamped JSON file under `chat_logs/`, containing session settings and role-tagged messages. `sample_conversation.json` is an example session included for reference. Runtime logs are excluded from Git by `.gitignore`.
